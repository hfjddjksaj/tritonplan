# Term Switcher — 学期切换与归档 · 设计文档

日期：2026-08-10
状态：已与用户逐块确认，待用户审阅本文档
范围：**纯 web 端**（`web/` + 少量 `shared/` 类型不动），**零扩展发版**

## 1. 背景与目标

TritonPlan 目前是单学期应用：`DEFAULT_TERM` 硬编码 Fall 2026（`web/src/lib/plan.ts:21`），所有
named plan 平铺在一个 `PlansState` 里，浏览池是跨学期一锅烩的扁平数组。学期结束后没有任何"翻篇"
机制，也无法回看过去学期选了什么。

目标：把顶栏的 "Term: Fall 2026" 升级为学期切换器——

- 数据按学期隔离：每个学期有自己独立的一组 plans 和浏览记录；
- 课程按自带学期自动归位（选下学期的课发生在本学期中间，这是常态而非边缘情况）；
- 过去学期只读封存，可回看、可分享，但不可再改；
- 新学期到来自动向前走，不用手动操作。

代码基础（2026-08-10 勘察）：`Term {year, period, label}` 类型、`CourseOffering.term`、课程 id 的
`|year|period` 后缀、`PlanState.term` 均已存在；缺的只是按学期组织的索引与 UI。

## 2. 已拍板的产品决策

| # | 决策 | 要点 |
|---|---|---|
| 1 | 学期在外层，plans 在内层 | 每学期一套完整的多 plan 体系 |
| 2 | 课程按自带 term 路由 + 自动切换视图 | 日期只决定默认显示，不决定数据归属 |
| 3 | 过去学期只读封存 | 封存时清空 Browsed，plan 内课程不动 |
| 4 | Browsed 完全独立 | 每个 plan 一份自己的清单（学期间、plan 间均独立） |
| 5 | 加课弹窗 | 目标学期多 plan 时在 **planner 侧**弹窗选 plan（扩展不知道 plan 列表，放 TSS 侧需发版） |
| 6 | 面板结构 | 上：三学期按学年行；一条大横线；下：夏季行。详见 §5 |
| 7 | 学期记法（全局统一） | Winter 跟随学年起始年（Fall 2026 后的冬季 = "Winter 2026"），Spring 用自然年 |
| 8 | 默认显示 | 永远显示时间线上最新的学期 |
| 9 | 归档边界 | 固定月-日近似（§6），不逐年维护日历 |

**考虑过但砍掉**：
- "半冻结态"（选课截止后 section 锁定、只删不加）——用户表示没想好，明确不做。若日后重提，
  当时讨论过的触发时点候选：官方加课截止日（第 2 周末）/ instruction 结束日 / ApptTimes 窗口结束。
- 方案 B（plan 平铺 + 派生过滤）与方案 C（每学期独立 storage key）——分别因不变量散落、过度设计被否。

## 3. 数据模型

```ts
// web 侧新增（extension 与 shared/types.ts 均不改）
type TermKey = string;                    // `${year}|${period}`，与课程 id 后缀同源

interface TermsState {
  version: 1;
  activeTermKey: TermKey;                 // 当前查看的学期
  terms: Record<TermKey, TermWorkspace>;
}
interface TermWorkspace {
  term: Term;                             // 沿用 shared 现有类型
  plans: PlansState;                      // 现有多 plan 容器原样复用，一学期一套
}
```

`NamedPlan` 变更：新增 `browsed: string[]`（本 plan 的浏览清单，存课程 id），**取代** `hidden`
机制（新存储形状里不再有 `hidden`）。浏览池数组（`pool:v1`）降级为纯"课程对象仓库"：按 id 存
`CourseOffering` 供各清单引用，不再直接是任何列表的显示来源。

`plans.ts` 的全部纯函数不改签名，作用对象从"全局唯一 PlansState"变为"当前学期的那套"。

### Browsed 独立清单的规则

- 新捕获的课只进"课程所属学期**当时的 active plan**"的清单；
- 新建 plan 清单从空开始；复制 plan 连清单一起带走；×/Clear 只动当前 plan；
- × 掉想找回：去 TSS 重新打开该课程（capturedAt 更新）→ 重新进当前 plan 清单；
- 加入 plan 的课同时保证在该 plan 的 browsed 清单里（显示时减掉在读条目），这样日后从 plan
  移除仍以浏览记录身份可见；
- "Clear all" 只清未加入的 id，已在 plan 里的课保留清单成员身份。

### 课程推送处理（`onCourses`，扩展每次全量推）

1. 课程对象照旧 `foldCourse` 合并进仓库；
2. 对"新出现的 id 或 capturedAt 变新"的课程：确保其学期工作区存在（不存在则创建，含一个默认
   plan），把 id 加进该学期 active plan 的 browsed 清单；
3. 视图切换用**增量判断**：本次新出现的课程若属于非当前学期，切到其中 capturedAt 最新的那个
   学期。座位数刷新（无新课）不引起跳转；已归档学期不刷新（冻结）。

已知可接受的边缘：在 TSS 打开某课程详情就算"重新浏览"，会把它加回当时 active plan 的清单——
打开详情视为有意行为，正是"找回"通道。

### "+ TritonPlan" 加课（plan 选择弹窗）

- 目标学期只有一个 plan → 直接加，行为同现在；
- 多个 plan → planner 聚焦后弹居中小窗（复用现有弹层壳），列出该学期各 plan 名，点谁加谁，
  加完 `activeTermKey` 切到该学期、active plan 切到所选 plan；
- Esc/取消 → 本次加课作废，课程仍以浏览记录留在清单（捕获本来就发生了）；
- 多门课排队（现有 DRAIN 队列）逐个询问；中途关页面，未确认的作废。

## 4. 存储与迁移

- 新 key `triton-planner:terms:v1` + `isTermsState` 校验；
- 一次性迁移（照抄 `purgeSeededSamples` 模式：标记先行、try/catch、纯函数）：把 `plans:v1`
  里现有 plans 按各自 `plan.term` 分组装进 TermsState（存量数据实际整体落进 Fall 2026）；每个
  plan 的 `browsed` 初始化为「仓库中匹配该学期的 id − 原 hidden − 已在 plan 内的 id」+「已在
  plan 内的 id」，即迁移前后用户看到的列表逐像素不变；
- 旧 key（`plans:v1`、`plan:v1`）保留不删作回滚后备；读取链：terms → plans（迁移）→ legacy
  单 plan（迁移）→ 空引导；
- 全新用户：引导期给一个 `DEFAULT_TERM` 空工作区；第一份真实捕获到达时若它仍是零课程即被
  真实学期顶替（避免陈旧的硬编码学期长期滞留）。

分享/导出**零改动**：三代分享格式的 term 字段本就齐全（`y/p/l`），received 视图自带学期，
`share.ts` / `share-v3.ts` 不碰——现有 share 测试原样通过即是"格式未动"的回归证明。

## 5. 切换器 UI

**入口**：顶栏 "Term: <label>" 原位改为可点按钮（▾ 角标）。点开在其下方**锚定**展开面板
（不居中）。移动端：现隐藏的 term 标签改为显示紧凑版，面板退化为底部 sheet（BlockSheet 先例）。

**面板结构**（上下两区块，一条大横线彻底分开；旧年份在上，新年份在下）：

```
┌──────────────────────────────────────────────┐
│ [ Fall 2026 ] [ Winter 2026 ] [ Spring 2027 ]│   ← 每学年一行，三格必满
│ [ Fall 2027 ] [ Winter 2027 ] [ Spring 2028 ]│
│ ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ │   ← 大横线
│ [ Summer I 2026 ]    [ Summer II 2026 ]      │   ← 每年一行，两格加宽，
│ [ Summer I 2027 ]    [ Summer II 2027 ]      │      总宽 = 上区块三格
└──────────────────────────────────────────────┘
```

- **灰格占位（不可点）**：某学年任一学期用过，该行其余学期灰显补齐；夏季行内只用过一个
  session 时另一格灰显。夏季区块（连同大横线）仅当至少一年用过夏季课才出现；
- 当前学期高亮；已归档学期可点、格内带小 "archived" 标记；
- 未知 period 代码的学期不参与学年分组，兜底 label 单独成行（自愈见 §7）；
- 点击可选学期 → 切 `activeTermKey`、关面板。

## 6. 学期时间线：默认显示、自动切换、归档

**默认显示（用户拍板：永远最新）**：打开应用一律落在时间线上最新的工作区，不记忆上次查看
（`activeTermKey` 随状态持久化只为会话内切换方便，加载时一律重置为最新学期，忽略存储值）。
最新学期已归档（新学期还没浏览任何课）就照常显示它 + archived 标记——去 TSS 浏览新学期课程
后，路由规则自动建区并切换。**不凭空造**未来学期工作区（其 SAP 代码在捕获到之前是未知的）。
应用开着时跨过边界不做实时切换，下次加载生效。

**归档边界**（固定月-日近似，一次写死零维护；具体日期每年浮动 ±1 周，但此时点只影响展示
与封存时机，差几天无伤大雅。依据 2026–27 官方日历：Fall 12/12 结束、Winter 3/20、Spring 6/11）：

| 学期 | 归档时点（该学期 finals 后的假期中） |
|---|---|
| Fall | 12/20 |
| Winter | 3/22 |
| Spring | 6/15 |
| Summer（两个 session 同点） | 9/15 |

**归档动作**（每次加载对"边界已过"的工作区执行；"是否归档"由日期纯函数推导，不存标记，
清理本身幂等）：

- 所有 plan 都没有任何课程 → 整个工作区删除（菜单里按学年占位规则变灰）；
- 有课程 → 保留为只读档案：各 plan 的 browsed 清单清空；仓库里不再被任何 plan 条目/清单
  引用的课程对象删除；向扩展发**已上架**的 `forget-courses` 消息释放扩展侧存储（plan 条目
  自带完整课程副本，无数据丢失）。这同时了结了"浏览池只增不减、localStorage 触顶"的已知隐患；
- 未知 period 代码的学期永不自动归档（算不出边界宁可不动）。

**只读实现**：单一闸口——`usePlan` 的修改类操作在目标学期已归档时一律 no-op；UI 层隐藏/禁用
×、Clear、plan 增删改名复制、加课弹窗（归档学期课程的 plan-add 理论上不会发生，防御性忽略 +
toast）；顶栏挂 archived 标记。查看、分享、导出、QR 照常。

## 7. 学期命名与 SAP 代码认知（集中一处）

新纯模块 `web/src/lib/terms.ts` 是全部"对 SAP 学期代码认知"的唯一落点：

- 季节映射：`'2' → Fall`（2026-07 实测）、`'3' → Winter`（appt fixture 强证据）；Spring/Summer
  代码未知——显示兜底 `Period N YYYY`、单独成行、不归档，捕获到真实数据后**改这一张表全部自愈**；
- 显示记法（用户拍板，全局统一）：Winter 显示学年起始年（"Winter 2026" = 2026-27 学年的冬季，
  即日历上的 2027 年 1–3 月），Spring/Fall/Summer 用自然年。仅显示层，存储与分享载荷的原始
  year/period 不动；
- 学年分行、时间线排序、归档边界、默认学期选择全部在此模块，均为纯函数；
- extension 的 `PERIOD_SEASON`（normalize.ts:32）**不依赖不阻塞**：web 自行按 year+period 推导
  显示名，扩展侧映射表可在未来任意发版时顺带补全。

**11 月（Winter 选课开放）待实测校准清单**——届时只改 `terms.ts`：
1. Winter/Spring 的 AcademicPeriod 代码；
2. Winter 的 `AcYear` 字段语义（学年 "2026" 还是自然年 "2027"）——影响分行/排序的年份换算方向；
3. TSS 界面自己显示的年份记法（与我们的记法对不上时提示用户知晓即可，记法不改）；
4. Summer 是一个还是两个 period 代码。

## 8. 错误处理

- `isTermsState` guard + `readJson` best-effort：坏数据走"迁移链 → 空引导"，永不抛给 UI（现有模式）；
- `forget-courses` 发送失败（未装扩展/孤儿 content script）：无妨，下次加载幂等重试；
- 未知 period：见 §7，一切兜底、不猜；
- 加课弹窗队列中途关页面：未确认的作废，课程留在浏览清单。

## 11. 验收标准

1. 存量用户升级后所见与升级前逐像素一致（Fall 2026 工作区，plan、Browsed 列表原样）;
2. 在 TSS 浏览/加入另一学期课程 → 工作区自动创建、视图自动切换、课程只出现在该学期当时的
   active plan 清单;
3. 目标学期多 plan 时加课弹窗出现且选择生效；单 plan 直加;
4. 切换器面板结构、灰格、夏季区块、记法与 §5/§7 一致;
5. 跨过归档边界后：空学期消失成灰格；非空学期只读、Browsed 清空、扩展收到 forget-courses;
6. 全仓 `npm test` / `typecheck` 绿，现有 share 测试零改动通过。
